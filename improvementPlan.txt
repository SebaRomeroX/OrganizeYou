ORGANIZEYOU - PORTFOLIO IMPROVEMENT PLAN
========================================

WHY THIS FILE EXISTS
--------------------
Grade as an IT recruiter would: 5/10 as a portfolio piece, while the
code itself deserves ~7/10. The gap is the story: the work is better
than the packaging, and recruiters only see the packaging. This file
lists every finding and the actions to close the gap. Target: 7.5-8/10.
All decisions, changes and progress are registered in this file, same
as the roadmap.

CURRENT GRADE: 5/10 (code: 7/10)  ->  ~7/10 after Phase 1 (2026-10-08)
                             ->  ~8/10 after Phase 2 (2026-10-08)
--------------------------------
Signals a recruiter sees in the first 30 seconds:
- README: MISSING - instant "incomplete" read, caps the grade alone.
- Live demo: NONE (no GitHub Pages) - they won't clone + open
  index.html to try it.
- Screenshots/GIF: NONE - a to-do app with zero visuals looks like a
  tutorial clone.
- Repo description/topics: "organizer/reminder app", no tags - not
  searchable, not contextualized.
- LICENSE: MISSING - reads as "student project", blocks reuse.
- Tests: NOT IN THE REPO - the roadmap claims Node test harnesses for
  goals 8-14, but git ls-files shows only 5 files. Unverifiable claim
  and it undermines the credibility of everything else.
- CI: NONE - no GitHub Actions at all.

What is genuinely strong (why the code gets a 7):
- docs/ROADMAP.md: 14 goals with decisions, checklists and a changelog -
  spec-driven discipline most junior devs cannot demonstrate.
- Defensive data handling: every localStorage load normalizes/migrates
  corrupt data; invalid entries are dropped instead of crashing.
- Pure, testable functions: countdownInfo, appointmentInfo,
  sinceInfo, doneCounts, dayStreak, nextCycleBoundary all take
  (input, now) - designed for testing even though tests are missing.
- Accessibility above average: role="dialog", aria-modal, aria-pressed
  chips, state-explaining aria-labels, Escape/backdrop close, focus
  restore, 44-48px touch targets, mobile-first.
- XSS-safe by construction: user text always via textContent, never
  innerHTML.
- Comments explain WHY, not what (DST reasoning, streak rules).
- 52 clean single-purpose commits, linear history, all pushed.

What drags the grade down:
1. app.js is 1,815 lines in the global scope - storage, domain
   logic, cycle math, badge formatting, modal orchestration and
   rendering interleaved. No modules, no 'use strict', no
   package.json. A tech lead sees a monolith.
2. Tests exist in the narrative but not in the repo (see above).
3. Polish misses: goal 14 task 9 still unchecked though the commit
   exists; no favicon / meta description / OG image; saveTasks() has
   no try/catch (QuotaExceededError throws uncaught); the modal has
   no focus trap (Tab leaves the dialog); the 60s setInterval is
   never cleared.
4. "Vanilla JS, no framework" is double-edged: half of recruiters
   filter FOR React/Vue, the other half respect the fundamentals
   argument - but nothing in the repo tells that story, so it reads
   as a default instead of a decision.
